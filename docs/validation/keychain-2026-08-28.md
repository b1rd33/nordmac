# Login Keychain validation — 2026-08-28

## Approved boundary

The user approved creating, reading, replacing, and deleting one synthetic generic-password item under service `com.github.b1rd33.nordmac.validation` in the login Keychain. Nord tokens, authenticated requests, and retained items were forbidden.

The unreleased harness generated random synthetic hex data in memory, used the fixed `access-token` account name, refused a pre-existing validation item, suppressed external stderr, and armed independent deletion before attempting the write.

## Result

The first `security add-generic-password ... -w` call returned success, but the immediate `security find-generic-password ... -w` returned an empty value. Replacement was not attempted. The harness treated the empty value as failure and its deferred cleanup deleted the exact validation item.

An independent lookup after the harness returned status 44 (`errSecItemNotFound`). No validation item remained. No Nord token was created or read, no authenticated request was made, and no non-validation Keychain item was selected or modified.

## Decision

The assumption that `security(1)` reliably reads the generic-password value from piped stdin when `-w` has no argument is false on the tested macOS 27 environment. A successful process exit is not evidence that the intended secret was stored.

The concrete `Store.Put` path now fails closed with `ErrWriteUnavailable` before invoking `security(1)`. `nordmac login` remains unavailable. Enabling writes requires an isolated integration test of a narrowly scoped native Security framework implementation or signed helper that accepts secret bytes outside argv and can target an explicit temporary Keychain.
